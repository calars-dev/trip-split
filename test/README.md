# 테스트

```bash
npm install   # 최초 1회 (jsdom만 받는다)
npm test
```

앱 자체는 여전히 **의존성이 없다.** `jsdom`은 테스트에서만 쓰고 배포되는 파일에는
들어가지 않는다. `index.html`과 `app.js`를 가짜 Supabase에 물려 브라우저 없이 돌린다.

| 파일 | 무엇을 지키나 |
|---|---|
| `timeline.test.js` | 일차·시간대 묶음과 정렬, 일차별 합계·막대, 멤버 필터. **세 사람 "나눈 것" 합계 = 전체 지출액**이 원 단위까지 맞는지 — 몫 계산이 정산과 어긋나면 여기서 걸린다. |
| `start-date.test.js` | 시작일을 고치면 일차가 따라 움직이는지. 갱신 순서(덮어쓰기 방지), 여러 날이 한꺼번에 준비로 모일 때 순서 재부여. |
| `drag.test.js` | 드래그로 옮겼을 때 **DB에 무엇이 쓰이는지**, 그리고 실제로 라이브에서 세 번 터진 모바일 버그들. |

## 이 테스트가 못 잡는 것

jsdom에는 레이아웃이 없다. `getBoundingClientRect()`가 전부 0이고 `touch-action`
개념이 없으며 캔버스도 없다. 그래서:

- **손가락 위치 판정**(어느 칸에 놓이는지)은 검증되지 않는다. 드래그 테스트는 rAF를
  멈추고 플레이스홀더를 손으로 옮긴 뒤 그 다음부터를 검증한다.
- **사진 축소·업로드**는 캔버스가 필요해 여기서 못 돈다. 실제 브라우저에서 확인한다.
- **`setPointerCapture`는 합성 이벤트에서 예외가 난다.** 이 때문에 캡처 관련 버그가
  테스트를 그냥 통과해버린 적이 있다(실제 손가락에서만 재현됐다).

정리하면 **데이터가 깨지는 것은 여기서 막고, 손가락으로 만지는 감각은 실제 기기에서
확인한다.** 이 경계를 헷갈리면 "테스트 통과했는데 폰에서 안 된다"가 반복된다.
