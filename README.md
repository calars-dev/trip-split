# ✈️ 여행 정산 (Trip Split)

친구들과의 여행 지출을 실시간으로 모으고, 여행이 끝나면 "누가 누구에게 얼마를
보내면 되는지"를 한 번에 계산해 주는 웹앱.

- 로그인 없음 (링크 공유 → 이름만 고르면 끝)
- 실시간 동기화 (한 명이 넣으면 모두 화면에 즉시 반영)
- 원(₩) · 엔(¥) 둘 다 입력, **정산은 원화 하나로 통합** (엔은 그날 환율로 환산)
- **일차·시간대 타임라인** — 며칠차 점심에 뭘 썼는지 흐름으로 보기
- **영수증 필수** — 새 지출은 영수증·결제내역 사진이 있어야 등록됨
- 다크 테마, 모바일 우선

## 🌅 아침에 할 일 — 딱 2가지

### 1. 데이터베이스 테이블 만들기 (30초, 최초 1회만)
1. https://supabase.com/dashboard 접속 → 내 프로젝트 선택
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. 이 폴더의 `schema.sql` 내용을 전부 복사해서 붙여넣기 → **Run** (▶)
4. "Success" 뜨면 끝. 앱이 바로 작동함.

### 2. 온라인 배포 (친구들이 접속할 링크 만들기)
- 로컬에서 먼저 써보려면: 이 폴더에서 `python -m http.server 8777`
  실행 후 폰 브라우저로 `http://<PC-IP>:8777` 접속.
- 공개 링크(GitHub Pages)는 `deploy.sh` 참고 — 또는 Claude에게 "배포해줘"라고 하면
  `calars-dev` 계정으로 올려줌.

## 사용 흐름
1. 앱 첫 접속 → 여행 이름·기본 통화·내 이름 입력 → **방 만들기**
2. 주소창에 `?r=xxxx` 링크가 생김 → 그 링크를 카톡으로 친구들에게 공유
3. 친구가 링크 열면 이름 선택(또는 새로 입력) → 바로 입력 화면
4. 지출 발생할 때마다: 금액 → 카테고리 탭 → 저장
   (기본값은 "지금 일차·시간대 · 내가 냄 · 전원 나눔")
5. 여행 끝나면 **현황 → 정산하기** → 송금 목록 확인

## 타임라인 (일차 · 시간대)

- 방을 만들 때 **여행 시작일**을 받는다. 그 날이 1일차다.
- 지출마다 `3일차 · 🌆저녁`처럼 붙는다. 기본값은 **지금 시각으로 자동**이라 현장에서
  넣을 땐 그냥 저장하면 되고, 뒤늦게 적을 때만 탭해서 고친다.
- 출발 전에 산 것(항공권·숙소·준비물)은 `🎒 여행 전 준비` 칸으로 간다. 여기엔
  시간대가 없다.
- `현황 → 타임라인`에서 일차별로 본다. 일차마다 그날 총액과 막대가 붙어서 어느 날
  크게 썼는지가 한눈에 보인다. 지출이 없는 날은 아예 안 나온다.
- 행 오른쪽 **`⋮⋮`를 꾹 눌렀다가 끌면** 아무 시간대·아무 일차로 옮겨진다. 준비
  구간으로도 내릴 수 있다. 드래그를 시작하면 빈 시간대까지 전부 펼쳐져 어디든 놓을 수
  있고, 놓으면 다시 접힌다. (지출을 탭해 **↑위로 / ↓아래로**로도 된다.)
  폰에서 **잠깐 누르고 있어야** 하는 이유는 손잡이가 엄지로 스크롤하는 자리에 있어서다.
  그냥 쓸어넘기면 평소대로 스크롤된다.
- **멤버 이름을 탭하면** 그 사람 기록만 본다(현황의 잔액 행 또는 타임라인 상단 칩).
  `낸 것`은 그 사람이 결제한 것, `나눈 것`은 그 사람이 부담하는 몫이다. 몫 계산은
  정산과 같은 규칙을 써서 합계가 어긋나지 않는다.

**1일차는 언제나 시작일이다.** 현황 화면의 `📅 여행 시작 …`으로 시작일을 고치면 지출은
실제로 있었던 날에 그대로 머물고 **일차 번호가 통째로 따라 움직인다.** 새 시작일보다
이른 것은 `🎒 여행 전 준비`로 내려간다. (준비로 내려간 것은 시작일을 다시 앞당겨도
준비에 남는다 — 달력 날짜를 저장하지 않아 되돌릴 근거가 없다. 직접 일차를 골라주면 된다.)

기존에 쓰던 방이라면 `migration-timeline.sql`을 한 번 실행한다. 시작일은 가장 이른
지출 날짜로 자동으로 채워지고, 기존 지출은 **입력한 시각**으로 일차·시간대가 배정된다.
출발 전에 결제한 항공권·숙소가 있으면 시작일이 그만큼 앞당겨 잡히므로, 현황 화면에서
실제 출발일로 고쳐준다. 나머지는 알아서 따라온다.

## 영수증

- 새 지출은 **영수증이나 결제내역 사진이 있어야 저장된다.** 입력 화면의 `📷 영수증 ·
  결제내역` 줄을 눌러 찍거나 사진첩에서 고른다.
- 사진은 **올라간 뒤에야 지출이 기록된다.** 데이터가 안 터지면 저장이 안 되고, 고른
  사진은 그대로 남아 있으니 연결이 돌아온 뒤 저장을 다시 누르면 된다.
- 폰 사진은 그대로 올리면 몇 MB씩 되므로 **브라우저에서 두 크기로 줄여** 올린다 —
  큰 것(가로세로 1400px, 금액 읽을 수 있는 수준)과 목록용 썸네일(220px).
- 목록에서는 카테고리 아이콘 자리에 **영수증 썸네일**이 뜨고 카테고리는 모서리
  배지로 남는다. 썸네일을 탭하면 **전체 화면**, 바깥을 누르거나 Esc로 닫는다.
  지출 자체를 열려면 행의 다른 곳을 탭한다.
- **필수는 새로 만드는 지출만** 해당한다. 이 규칙 이전에 넣은 지출은 수정이 막히지
  않는다. 나중에 붙이려면 지출을 탭해 `📷 영수증 첨부`를 누른다.
- `migration-receipt.sql`을 한 번 실행해야 동작한다. 실행 전에는 필수 검사가 꺼지고
  안내만 뜬다 — 넣을 데가 없는데 필수로 걸면 앱 전체가 잠기기 때문이다.

> ⚠️ 이미지 버킷은 **공개**다. 링크를 아는 사람은 볼 수 있다(방 링크 자체가 이미 그런
> 모델이다). 카드번호가 찍힌 명세서를 올릴 때는 알고 올린다.

## 환율 (엔 → 원)
- 엔화 지출을 **저장하는 순간** 그날 환율을 받아와 그 지출에 박아둔다. 나중에 환율이
  움직여도 이미 계산된 정산 금액은 안 바뀐다.
- 출처는 [frankfurter](https://frankfurter.dev) (ECB 기준환율, API 키 불필요).
  주말·공휴일이면 직전 영업일 환율이 쓰인다.
- 오프라인이라 환율을 못 받으면 **방 기준 환율**(마지막으로 성공한 값)로 저장하고
  `⚡기준환율` 배지를 붙인다. 저장이 막히는 일은 없다. 지출을 탭해 직접 고칠 수 있다.
- ECB 중간환율이라 **카드사 실제 청구액과 1~2% 차이**가 난다. 정확히 맞추려면
  지출 → `💱 환율 수정`으로 직접 넣는다.

> 이 방(교토)은 `migration-rate.sql`을 **일부러 안 돌렸다.** 엔화 지출은 그날 환율이
> 아니라 방 기준 환율 하나로 환산되고 `⚡기준환율` 배지가 붙는다. 지금 돌려도 이미
> 들어간 지출엔 소급 적용되지 않는다(그날 환율을 되찾을 방법이 없다).

## 알아둘 점
- 링크를 아는 사람은 그 방의 데이터를 보고 수정할 수 있음 (친구 여행용 위협 모델).
