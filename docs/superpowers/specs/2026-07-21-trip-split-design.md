# Trip Split — 여행 정산 웹앱 설계

작성일: 2026-07-21
대상: 친구 5명 여행 총무용 실시간 공동 가계부 + 정산

## 1. 목적

여행 중 각자 쓴 돈을 실시간으로 모으고, 여행이 끝나면 "누가 누구에게 얼마를
보내면 되는지"를 한 번에 계산해 주는 웹앱. 총무(사용자)의 정산 부담 제거가 목표.

## 2. 핵심 원칙

- **입력이 1순위.** 앱을 열면 곧바로 금액 입력 화면. 최단 경로 3동작(금액 → 카테고리 → 저장).
- **로그인 없음.** 링크 공유 → 처음 들어온 사람은 이름 입력 또는 기존 이름 선택 → 폰에 기억.
- **실시간.** 한 명이 지출을 넣으면 나머지 화면에 즉시 반영(Supabase Realtime).
- **과하지 않은 보안.** 링크를 아는 사람만 접근. 친구 여행 가계부에 적정한 수준.

## 3. 화면 구성

### ① 입력 (메인, 앱 진입 시 첫 화면)
- 화면 주인공 = **금액**(크게). 폰 기본 숫자 키보드 사용(자체 키패드 없음, `inputmode=numeric`).
- 통화 토글 ₩/¥ (기본값 = 방의 기본 통화).
- 카테고리 태그 8개: 🍚식비 ☕카페 🚕교통 🏠숙소 🎁선물 🛒마트 🍺술 ➕기타.
  탭 한 번으로 확정. 내용 글 입력은 선택.
- "○○가 냄 · N명이 나눔" 한 줄 요약. 기본값(낸 사람=나, 나눔=전원). 탭하면 펼쳐서 변경.
- 저장 → 짧은 확인 표시 후 즉시 빈 입력 화면(연속 입력 대비).

### ② 현황 (우상단 "현황 →"으로 진입)
- 총 지출, 1인 평균(통화별로).
- 사람별 잔액: (낸 돈 − 낼 돈). 초록=받을 사람, 빨강=낼 사람.
- 최근 지출 목록.
- 맨 아래 **[정산하기]** 버튼 → 누가 누구에게 얼마(통화별로 분리) 결과 펼침.

### ③ 내역 (전체 지출 목록)
- 지출 항목 탭 → 수정/삭제.

## 4. 통화 처리

- KRW·JPY 둘 다 지원. **환율 변환 없음.**
- 통화는 지출별 속성. 방은 기본 통화 하나를 가짐(입력 시 기본값).
- 잔액·정산은 **통화별로 따로 계산**해서 표시(예: "민수 → 지훈 ¥5,000 + ₩10,000").
- KRW·JPY 모두 소수점 없는 정수 통화라 금액은 정수(bigint)로 저장.

## 5. 데이터 모델 (Supabase / Postgres)

```
rooms
  id text PK              -- URL 슬러그
  name text
  default_currency text   -- 'KRW' | 'JPY'
  created_at timestamptz

members
  id uuid PK
  room_id text FK -> rooms.id
  name text
  created_at timestamptz

expenses
  id uuid PK
  room_id text FK -> rooms.id
  payer_id uuid FK -> members.id
  amount bigint           -- 정수(원/엔)
  currency text           -- 'KRW' | 'JPY'
  category text
  note text
  participant_ids uuid[]  -- 나눠 갖는 멤버 id 배열
  created_at timestamptz
```

- 참여자는 join 테이블 대신 `participant_ids` 배열로 저장(5명 규모, 실시간 단순화).
- RLS 활성화 + anon 전체 허용 정책(로그인 없는 앱, 링크 기반 접근 모델).
- 세 테이블 모두 `supabase_realtime` publication에 추가.

## 6. 정산 알고리즘

1. 통화별로 분리.
2. 각 지출: 낸 사람 +amount, 나눔 인원에게 각 −(amount / 나눔인원수). 나머지(원 단위) 처리:
   1원/1엔 단위 반올림 오차는 낸 사람 쪽으로 흡수.
3. 멤버별 순잔액 산출(+받을 돈 / −낼 돈).
4. 최소 송금 횟수 정산: 가장 많이 낼 사람 → 가장 많이 받을 사람 순으로 그리디 매칭.

## 7. 클라이언트 신원

- localStorage에 `{room_id: member_id}` 저장 → "나"를 기억.
- 방 링크: `index.html?r=<room_id>`.
- 방이 없으면(파라미터 없음) 방 생성 화면(이름 + 기본 통화) → 슬러그 생성.
- 링크로 들어왔는데 내 멤버 기록이 없으면 이름 선택/입력 화면.

## 8. 기술 스택

- 프론트: 단일 `index.html`(자체 CSS/JS). Tailwind 등 CDN 스타일 의존 없음.
- `@supabase/supabase-js` UMD를 `vendor/`에 vendoring(런타임 CDN 의존 제거).
- 백엔드: Supabase(Postgres + Realtime), 무료 티어.
- 배포: GitHub Pages(`calars-dev` 계정, 개인 프로젝트).

## 9. 비UI 결정 / 기본값

- 다크 테마 기본(밤·어두운 이동 중 사용 가정).
- 방 이름은 앱 내에서 수정 가능.
- 저장은 낙관적 UI(즉시 화면 반영, 서버 확인 후 정정).

## 10. 알려진 한계

- 링크를 아는 사람은 데이터 열람·수정 가능(의도된 위협 모델).
- 통화 간 환율 정산은 하지 않음(통화별 분리 정산).
- 테이블 생성 DDL은 anon 키로 불가 → 최초 1회 사용자가 SQL 실행 필요(`schema.sql`).
