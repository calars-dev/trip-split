# 영수증 첨부 — 설계

**작성일** 2026-07-28
**대상** trip-split (여행 정산 웹앱)

지출에 영수증·결제내역 사진을 붙인다. **새로 만드는 지출은 사진이 있어야 저장된다.**
목록에서 썸네일로 훑어보고, 탭하면 크게 본다.

## 어디에 저장하나

Supabase Storage의 `receipts` 버킷. 대안이었던 "DB에 base64로 넣기"는 탈락이다 —
이 앱은 화면을 그릴 때마다 방의 **모든 지출을 통째로 받아오므로**, 이미지가 행 안에
들어 있으면 새로고침 한 번에 수십 MB를 내려받게 된다.

`expenses.receipt_path`에는 **키만** 넣는다(예: `ttgkxsg/a1b2c3d4e5f6`). 실제 파일은
두 개다.

| 파일 | 크기 | 용도 |
|---|---|---|
| `<키>.jpg` | 긴 변 1400px, q0.82 | 탭했을 때 크게 보기 |
| `<키>_t.jpg` | 긴 변 220px, q0.7 | 목록 썸네일 |

**두 장을 따로 두는 이유**는 목록 때문이다. 여행 하나에 지출이 50건이면 큰 사진
50장이 한꺼번에 뜬다. 썸네일은 장당 10KB 안팎이라 부담이 없다.

**축소는 브라우저에서 한다.** 폰 사진은 3~5MB고, 그대로 올리면 해외 데이터로는
저장이 하세월이다. 캔버스로 줄여서 올린다. (EXIF 회전은 요즘 브라우저가 `<img>`
디코딩 단계에서 이미 적용하므로 따로 처리하지 않는다.)

## 공개 버킷이다

버킷은 `public: true`다. **URL을 아는 사람은 누구나 볼 수 있다.**

이 앱은 로그인이 없고 방 링크 자체가 유일한 열쇠다("링크를 아는 사람은 그 방의
데이터를 보고 수정할 수 있음" — 기존 위협 모델). 이미지도 같은 모델을 따른다.
서명 URL을 쓰면 더 좁힐 수 있지만, 만료 관리가 붙는 데 비해 **지키는 비밀의 등급이
올라가지 않는다** — 링크가 새면 어차피 다 보인다.

⚠️ 다만 영수증에는 카드번호 뒷자리가 찍히는 경우가 있다. README에 명시했다.

## 필수 규칙

- **새 지출만 필수.** 이 규칙 이전에 들어간 49건은 필수에서 제외한다. 그러지 않으면
  기존 지출이 **수정 불가능해진다**(수정 저장에도 검사가 걸리므로).
- **업로드까지 끝나야 저장한다**(사용자 결정, 2026-07-28). 사진이 스토리지에 올라간
  뒤에 행을 쓴다. 순서를 뒤집으면 **없는 사진을 가리키는 지출**이 생긴다.
- 업로드가 실패하면 저장을 멈추고, **고른 사진은 draft에 그대로 둔다.** 연결이
  돌아온 뒤 저장을 다시 누르면 된다.

> 이 규칙은 "저장은 절대 막지 않는다"는 이 앱의 기존 원칙과 정면으로 충돌한다.
> 환율을 못 받아와도 저장하고, SQL이 안 돌아간 DB에서도 칸을 떼고 저장해 왔다.
> 사용자에게 트레이드오프(지하 식당에서 데이터가 안 터지면 기록을 못 남긴다)를
> 명시적으로 제시했고, 엄격 쪽을 택했다. 나중에 뒤집는다면 "사진은 받고 업로드는
> 나중에 재시도" 방식이 후보다.

## SQL을 안 돌린 DB

부팅할 때 `select("receipt_path").limit(1)`로 **한 번 확인한다.**

- 칸이 없으면 `receiptColMissing`을 켜고 **필수 검사를 끈다.** 넣을 데가 없는데
  필수로 걸면 앱 전체가 잠긴다.
- 입력 화면에 "`migration-receipt.sql`을 실행해 주세요" 안내를 띄운다.
- 저장 payload에서 `receipt_path`를 떼는 것은 기존 `sanitize()` 흐름에 얹는다
  (환율 칸·타임라인 칸과 같은 방식, 재시도 3회로 확장).

**이 확인은 try/catch로 감싼다.** 여기서 예외가 새면 `boot()`가 거기서 멈춰
화면이 "불러오는 중…"에 영영 갇힌다. 실제로 개발 중 한 번 그렇게 됐다.

## 화면

**입력 화면** — 내용 입력칸 아래 한 줄. 기본은 `📷 영수증 · 결제내역 **필수**`,
고르면 그 자리에 썸네일과 "첨부됨". 첨부 없이 저장을 누르면 막고 **바로 선택창을
연다**(막기만 하면 사용자가 어디를 눌러야 하는지 찾아야 한다).

**목록** — 영수증이 있으면 카테고리 아이콘 자리를 썸네일이 차지하고, 카테고리는
오른쪽 아래 작은 배지로 남는다. 폰에서 행이 더 넓어질 수 없어서 자리를 새로
만들지 않고 바꿔치기했다. `loading="lazy"`.

**크게 보기** — 전체 화면 오버레이. **바깥을 누르면 닫히고 이미지 자체를 누르면
안 닫힌다.** Esc도 닫는다. 닫을 때 `src`를 비워 느린 로딩을 끊는다.

썸네일 탭은 `stopPropagation`으로 지출 모달을 막는다. 행의 다른 곳을 탭하면 평소대로
지출 모달이 열린다.

**기존 지출에 붙이기** — 지출 모달에 `📷 영수증 첨부`(없을 때) / `🧾 영수증 보기`
(있을 때). 49건에 나중에 붙일 수 있어야 한다.

## 안 하는 것

- **서명 URL / 비공개 버킷** — 위 참조. 지키는 비밀의 등급이 안 올라간다.
- **여러 장 첨부** — 영수증은 보통 한 장이다. 필요해지면 `receipt_path`를 배열로
  바꾸는 게 자연스럽다.
- **오프라인 큐(사진 보관 후 나중에 업로드)** — 사용자가 엄격 쪽을 택했다.
- **영수증 삭제** — 교체는 되지만(다시 고르면 새 키로 덮어씀) 지우기는 없다.
  옛 파일은 스토리지에 남는다. 여행 하나에 수십 장 수준이라 방치해도 무해하다.
